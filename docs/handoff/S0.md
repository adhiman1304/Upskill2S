- **Schema + migration**: `prisma/schema.prisma` gains the `Certification` fields (`officialUrl`, `aliases`, `isCatalog`, `lastResearchedAt`), the seven models from plan section 4, inverse relations on `User` (`providerKeys`, `researchJobs`, `studyBriefs`, `checklistProgress`, `briefFeedback`, `followedCertifications`, `intakeSessions`) and on `Certification` (`researchJobs`, `studyBriefs`, `checklistProgress`, `followers` = `UserCertification[]`). Migration: `prisma/migrations/20261021211246_ai_rework_foundation/`.
- **Seed placeholder**: `prisma/seed/catalog.json` (5 exams: AZ-900, DP-700, SAA-C03, Google ACE, SY0-701) and `prisma/seed/README.md`. Entry shape is also exported as `catalogSeedEntrySchema` / `CatalogSeedEntry`. No seed script (D owns `seed.ts`).
- **Config**: `server/.env.example` and `server/src/config.ts` add `keyEncryptionSecret`, `openAiResearchModel`, `openAiFastModel`, `openAiServerApiKey` (`string | null`), `researchMaxWebSearches`, `briefStaleDays`, `blockedResearchDomains` (lower-cased `string[]`), `schedulerEnabled`, `schedulerCron`, `intakeMaxFiles`, `intakeMaxFileBytes`. If `KEY_ENCRYPTION_SECRET` is missing, startup throws unless local auth bypass is on; with bypass on, a fixed dev fallback is used and a warning is printed once. A secret shorter than 32 chars throws outside bypass.
- **Crypto**: `server/src/lib/crypto.ts`: `encryptSecret` / `decryptSecret`, AES-256-GCM, HKDF-SHA256 key derivation, random 12-byte IV, format `v1:<iv>:<tag>:<ciphertext>` (base64). Round-trip and tamper detection were checked.
- **Contracts**: `server/src/lib/contracts/{brief,intake,jobs,settings,catalog,index}.ts`. Zod schemas plus inferred types for everything in 5.1 and 5.2, plus the `ApiErrorCode` / `ApiErrorBody` types.
- **OpenAI**: `server/src/services/openai/models.ts` (`openAiModels`) and `client.ts` (`MissingApiKeyError`, `getOpenAIClientForUser`, `getServerOpenAIClient`, `validateOpenAIKey`; `client.ts` also re-exports `openAiModels`).
- **Jobs**: `server/src/services/jobs/queue.ts`, `dto.ts` (`jobDto`, `parseJobProgress`) and `handlers.ts` (`registerHandlers`). The worker is wired into `server/src/index.ts`, which runs `registerHandlers()`, then `await recoverInterruptedJobs()`, then `startJobWorker()`. On SIGINT/SIGTERM the server calls `stopJobWorker()`, which aborts `ctx.signal` and waits up to 5 s.
- **Stubs**: `services/research/index.ts` (A), `services/intake/index.ts` (C), `services/catalog/index.ts` (D); routers `routes/{catalog,briefs,jobs,intake,admin-ops}.ts` (all return 501 `NOT_IMPLEMENTED`).
- **Settings (real)**: `routes/settings.ts` provides GET, PUT and DELETE `/api/settings/openai-key`.

### Contracts

- `studyBriefContentSchema` is plain: every object is `z.strictObject`, every key is required, missing values are `.nullable()`, there are no transforms, string formats or string lengths, and ids use a kebab-case `pattern`. `checklist` uses `.min(10).max(25)`. `zodTextFormat(studyBriefContentSchema, 'study_brief')` from `openai/helpers/zod` was checked and produces a strict `json_schema` format (A).
- `validateBriefContent(content)` returns a zod `safeParse` result. It checks that every `sourceIds` entry exists in `sources`, that source ids and per-section item ids are unique, and that every URL (sources, `officialUrl`, learning path, community resources, checklist links) uses HTTPS. Use it on LLM output before persisting (A).
- `intakeResultSchema` follows the same strict LLM-friendly rules (C).

### Jobs (A, B, C, E)

- Handlers receive `JobContext`. Pass `ctx.signal` to OpenAI calls, and call `ctx.log(msg)` for progress (messages are cut at 500 chars; never log keys).
- Choose the client with `ctx.useServerKey ? getServerOpenAIClient() : await getOpenAIClientForUser(ctx.requestedById)`.
- Failure messages: only messages from `UserFacingJobError` and `MissingApiKeyError` reach the user verbatim. OpenAI 401 and 429 map to fixed friendly messages, an abort maps to "server shut down", and anything else becomes "The job failed unexpectedly. Try again later." The full error always goes to the console.
- `handlers.ts` maps `runBriefResearch`'s `{ briefId }` to the job's `resultBriefId`.
- `enqueueJob` does not check for duplicates. Routes should call `findActiveJob({ certificationId })` first and return 409 `JOB_ALREADY_RUNNING` (B).
- The queue does not update `IntakeSession.status`; the intake handler owns that (C). `recoverInterruptedJobs` only touches `ResearchJob` rows. C may want to fail matching RUNNING intake sessions on boot as well.
- Without a started worker (for example A's CLI script), jobs stay QUEUED. The CLI should call `runBriefResearch` directly with a hand-built `JobContext`.

### Routers and mounts (`routes/api.ts`, after `router.use(requireAuth)` and before legacy routes)

| Router | Mount | Paths defined inside |
|---|---|---|
| `settingsRouter` | `/settings` | relative (`/openai-key`) |
| `catalogRouter` (D) | `/catalog` | relative (`/search`, `/resolve`) |
| `adminOpsRouter` (E) | `/admin/ops` | relative (`/summary`, `/jobs`, `/refresh-stale`); add `isAdmin` checks |
| `briefsRouter` (B) | API root | **full** paths: `/certifications/:id/brief{/*splat}`, `/certifications/:id/follow`, `/briefs/:briefId/feedback` |
| `jobsRouter` (B) | API root | **full** paths: `/jobs/...`, `/me/jobs` |
| `intakeRouter` (C) | API root | **full** paths: `/intake/...`, `/me/intake` |

Root-mounted routers must only declare their own specific paths; never add `router.use(...)` middleware without a path, because that would run for every legacy request. Each stub applies `requireAuth` per route; prefix-mounted stubs use `router.use(requireAuth)`. For multipart intake uploads, add multer on the route itself, since the global `express.json` limit is 1 MB.

### Settings API (D client)

- `GET` returns `OpenAiKeyStatusDto`.
- `PUT {apiKey}` validates the key against OpenAI (`models.list`, no retries, 15 s timeout). It returns 400 `{error, code:'OPENAI_KEY_INVALID'}` for a bad shape or a rejected key; otherwise it stores the key and returns the DTO.
- `DELETE` returns 204.
